# § 7.5. Читаемость: имена, комментарии, структура

В § 7.4 мы разбирали, что замедляет код. Теперь — третье измерение качества: читаемость. Код пишут один раз, а читают многократно — и чаще всего не его автор. Через полгода даже сам автор смотрит на свой код как на чужой. Читаемый код — это код, который объясняет себя сам.

---

## 1. Именование: главный инструмент читаемости

Самый мощный способ сделать код понятным — давать осмысленные имена переменным, процедурам и функциям.

**Принцип: имя должно говорить о содержимом, а не о типе.**

```bsl,песочница
// Плохо: непонятно, что хранит
К = 0;
С = "";
Д = ТекущаяДата();

// Хорошо: имена говорят о смысле
КоличествоТоваров = 0;
НаименованиеКлиента = "";
ДатаСоздания = ТекущаяДата();
```

Частые антипаттерны именования в 1С:

```
  Антипаттерн        Лучше
  ─────────────────  ─────────────────────────────
  К, Н, С, Д        Счётчик, Номер, Сумма, Дата
  Тмп, Тмп1, Тмп2   конкретное имя по смыслу
  Переменная1        что хранится в переменной?
  Объект             Документ, Контрагент, Товар
  Флаг               НайденоСовпадение, ЕстьОшибка
```

---

## 2. Имена процедур: глагол + объект

Процедуры и функции — это действия. Их имена должны начинаться с глагола и называть объект действия:

```
// Плохо: непонятно, что делает
Процедура Обработка()
Процедура П1()
Функция Расчёт()

// Хорошо: глагол + объект
Процедура ОбновитьЦеныНоменклатуры()
Процедура ПровестиДокументПоступления(Ссылка)
Функция РассчитатьСуммуСкидки(Сумма, Процент)
```

Имя процедуры — это документация. Встретив `ОбновитьЦеныНоменклатуры()` в чужом коде, не нужно читать её тело, чтобы понять назначение.

> **Имя процедуры — это документация: читатель кода должен понимать назначение по имени, не заглядывая в тело.**

---

## 3. Комментарии: почему, а не что

Плохой комментарий описывает *что* делает код — это уже видно из кода. Хороший комментарий объясняет *почему* выбрано именно такое решение.

```
// Плохо: очевидно и без комментария
// Увеличиваем цену на 10%
НовАяЦена = Цена * 1.1;

// Плохо: устаревший комментарий (хуже, чем отсутствие)
// Умножаем на 0.9 для скидки
НовАяЦена = Цена * 1.1; // код противоречит комментарию!

// Хорошо: объясняет причину решения
// Коэффициент 1.1 — согласовано с директором 15.01.2025
// (письмо № 47). При изменении ставки обновить эту константу.
НовАяЦена = Цена * 1.1;
```

Когда комментарий нужен обязательно:
- Нетривиальное бизнес-правило («скидка 5% для клиентов категории VIP начиная с суммы 50 000»).
- Обходной путь («так работает из-за особенности версии платформы 8.3.22»).
- Внешняя зависимость («этот код вызывается только из регламентного задания, не вручную»).

> **Комментарий — не пересказ кода. Комментарий — объяснение решения: почему именно так, а не иначе.**

---

## 4. Одна процедура — одна задача

Читаемость нарушается, когда одна процедура делает слишком много. Признаки:

- Процедура занимает больше 50–70 строк.
- Её название содержит «И»: `НайтиИОбновитьИЗаписать()`.
- Комментарий «часть 1», «часть 2», «часть 3» внутри одной процедуры.

Длинная процедура разбивается на несколько коротких вспомогательных. Каждая — одна ответственность, одно имя:

```bsl,песочница
// Плохо: одна большая процедура
Процедура ОбработкаДокумента(Ссылка)
    // проверить заполненность...
    // найти склад...
    // посчитать сумму...
    // провести...
    // отправить уведомление...
КонецПроцедуры;

// Хорошо: делегирование в вспомогательные процедуры
Процедура ОбработкаДокумента(Ссылка)
    Если НЕ ПроверитьЗаполненность(Ссылка) Тогда
        Возврат;
    КонецЕсли;
    СкладСсылка = ОпределитьСклад(Ссылка);
    ИтогоСумма  = РассчитатьСумму(Ссылка);
    ПровестиДокумент(Ссылка);
    ОтправитьУведомление(Ссылка, ИтогоСумма);
КонецПроцедуры;
```

Главная процедура стала короткой и читается как план действий — без погружения в детали каждого шага.

## 5. Магические числа и строки

**Магическое число** — числовое (или строковое) значение прямо в коде, без объяснения смысла:

```
// Плохо: что такое 0.05? что такое 50000?
Если СуммаЗаказа > 50000 Тогда
    Скидка = СуммаЗаказа * 0.05;
КонецЕсли;

// Хорошо: смысл виден из имён
ПорогСкидки   = 50000; // сумма, начиная с которой действует скидка
ПроцентСкидки = 0.05;  // 5% — ставка скидки для оптовых клиентов
Если СуммаЗаказа > ПорогСкидки Тогда
    Скидка = СуммаЗаказа * ПроцентСкидки;
КонецЕсли;
```

Если значение изменится — найти и поменять в одном месте, а не искать все вхождения `50000` по коду.

## 6. Канцтовары: до и после

Рассмотрим реальный фрагмент «как есть» и «как стало» после улучшения читаемости.

**До (работающий, но трудночитаемый):**

```bsl,песочница
Процедура П(Д)
    В = Документы.ПоступлениеТоваров.Выбрать(Д, Д);
    С = 0;
    Пока В.Следующий() Цикл
        Если В.Проведён Тогда
            С = С + В.СуммаДокумента;
        КонецЕсли;
    КонецЦикла;
    Сообщить(С);
КонецПроцедуры;
```

**После (тот же алгоритм, читаемый):**

```bsl,песочница
// Подсчитать суммарный объём проведённых поступлений за указанную дату
Функция ПодсчитатьПоступленияЗаДату(ДатаПоиска)
    НачалоДня = НачалоДня(ДатаПоиска);
    КонецДня   = КонецДня(ДатаПоиска);

    ИтогоПоступлений = 0;
    Выборка = Документы.ПоступлениеТоваров.Выбрать(НачалоДня, КонецДня);
    Пока Выборка.Следующий() Цикл
        Если Выборка.Проведён Тогда
            ИтогоПоступлений = ИтогоПоступлений + Выборка.СуммаДокумента;
        КонецЕсли;
    КонецЦикла;

    Возврат ИтогоПоступлений;
КонецФункции;
```

Изменения:
- Процедура стала функцией (возвращает значение, а не выводит его — гибче для повторного использования).
- Имена: `П` → `ПодсчитатьПоступленияЗаДату`, `Д` → `ДатаПоиска`, `В` → `Выборка`, `С` → `ИтогоПоступлений`.
- Добавлен комментарий с назначением.
- Введены `НачалоДня` и `КонецДня` — ясно, что именно передаётся в `Выбрать()`.

---

## Главное в одном абзаце

Читаемость определяется тремя факторами. **Именование**: имена переменных — по содержимому, процедур — глагол + объект; антипаттерны (`К`, `О`, `Тмп`) затрудняют понимание. **Комментарии**: объясняют почему, а не что; устаревший комментарий хуже отсутствия. **Структура**: одна процедура — одна задача; длинные процедуры дробят на вспомогательные; магические числа заменяют именованными переменными. Читаемый код объясняет себя сам — его можно понять без вопросов к автору.

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

```

        ВсеТоварыДешёвые = Ложь;
    КонецЕсли;
КонецЦикла;
```

**К упражнению 2.** *Полное решение.*

(а) Плохой — описывает очевидное. «Устанавливаем значение в Истина» видно из кода. Нужно или убрать, или объяснить зачем: «Документ считается проведённым после подтверждения директором».

(б) Хороший — объясняет причину нетривиального числа: кто договорился, когда, какая ставка. Это именно то, что комментарий должен делать.

(в) Плохой — «TODO: исправить потом» без указания, что именно и когда. Со временем становится мусором. Лучше: «TODO: заменить заглушку реальным расчётом после готовности интеграции с поставщиком (задача JIRA-1234)».

**К упражнению 3.** *Полное решение.*

```bsl,песочница
Функция ЗаказЯвляетсяКорректным(ЗаказСсылка)
    Если НЕ ЗначениеЗаполнено(ЗаказСсылка) Тогда
        Возврат Ложь;
    КонецЕсли;
    Объект = ЗаказСсылка.ПолучитьОбъект();
    Возврат Объект.Товары.Количество() > 0;
КонецФункции;

Функция РассчитатьСуммуЗаказа(ОбъектЗаказа)
    ИтогоСумма = 0;
    Для каждого Строка Из ОбъектЗаказа.Товары Цикл
        ИтогоСумма = ИтогоСумма + Строка.Сумма;
    КонецЦикла;
    Возврат ИтогоСумма;
КонецФункции;

Процедура СохранитьЗаказССуммой(ОбъектЗаказа, ИтогоСумма)
    ОбъектЗаказа.ИтогоСумма = ИтогоСумма;
    ОбъектЗаказа.Записать();
КонецПроцедуры;

Процедура ОбработатьЗаказ(ЗаказСсылка)
    Если НЕ ЗаказЯвляетсяКорректным(ЗаказСсылка) Тогда
        Возврат;
    КонецЕсли;
    Объект     = ЗаказСсылка.ПолучитьОбъект();
    ИтогоСумма = РассчитатьСуммуЗаказа(Объект);
    СохранитьЗаказССуммой(Объект, ИтогоСумма);
КонецПроцедуры;
```

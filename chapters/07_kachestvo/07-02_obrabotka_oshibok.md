# § 7.2. Обработка ошибок: Попытка и Исключение

В § 7.1 мы выяснили, что надёжность — это способность кода вести себя предсказуемо при неожиданных ситуациях. Самая непредсказуемая ситуация — ошибка: что-то пошло не так, платформа не может выполнить операцию. Для таких случаев в 1С есть специальная конструкция — `Попытка / Исключение`. Это единственная принципиально новая синтаксическая конструкция Модуля 7; остальные параграфы будут применять уже знакомые инструменты к новым задачам.

---

## 1. Что такое ошибка выполнения

До сих пор мы рассматривали ситуации, когда что-то «не найдено» или «не заполнено» — они обрабатываются обычными условиями (`Если НЕ ЗначениеЗаполнено(...)`). Это контролируемые ситуации.

Но есть другой класс ситуаций — **ошибки выполнения**, которые платформа не может обойти сама:

- Попытка записать объект, который заблокирован другим пользователем.
- Нарушение уникальности: документ с таким номером уже существует.
- Ошибка соединения с внешней системой.
- Деление на ноль.

В таких ситуациях платформа «бросает исключение» — прерывает выполнение и сообщает об ошибке. Если исключение не перехватить, выполнение текущей процедуры остановится и пользователь, как правило, увидит системное сообщение без понятного объяснения.

---

## 2. Конструкция `Попытка / Исключение`

```bsl,песочница
Попытка
    // Код, который может вызвать ошибку
Исключение
    // Что делать, если ошибка произошла
КонецПопытки;
```

Платформа выполняет код в блоке `Попытка`. Если ошибка не возникает — блок `Исключение` пропускается. Если ошибка произошла — выполнение немедленно переходит в блок `Исключение`, где можно обработать ситуацию.

После `КонецПопытки` выполнение продолжается в обычном порядке — если в блоке `Исключение` не было `Возврат` или повторного вызова ошибки.

> **`Попытка / Исключение / КонецПопытки` — конструкция для перехвата ошибок. Без неё ошибка, как правило, прервёт выполнение процедуры с системным сообщением.**

---

## 3. Функция `ОписаниеОшибки()`

Внутри блока `Исключение` доступна глобальная функция `ОписаниеОшибки()` — она возвращает строку с текстом ошибки, которую платформа зафиксировала. Используется для логирования или вывода понятного сообщения:

```bsl,песочница
Попытка
    Объект.Записать(РежимЗаписиДокумента.Проведение);
Исключение
    Сообщить("Не удалось провести документ: " + ОписаниеОшибки());
КонецПопытки;
```

---

## 4. Типичный паттерн: запись с обработкой ошибки

Самое частое применение `Попытка` — при записи или проведении объектов:

```
Ссылка = Документы.ПоступлениеТоваров.НайтиПоНомеру("ПТ-000052");
Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
    Сообщить("Документ не найден");
    Возврат;
КонецЕсли;

Объект = Ссылка.ПолучитьОбъект();

Попытка
    Объект.Записать(РежимЗаписиДокумента.Проведение);
    Сообщить("Документ проведён успешно");
Исключение
    Сообщить("Ошибка при проведении: " + ОписаниеОшибки());
КонецПопытки;
```

Порядок такой: сначала — обычные проверки (`ЗначениеЗаполнено`), потом — операция в `Попытка`. Исключение — для ситуаций, которые нельзя предсказать заранее.

---

## 5. Когда использовать `Попытка`, а когда — `Если`

Начинающие нередко спрашивают: зачем два разных механизма? Ответ — в природе ситуации.

**`Если НЕ ЗначениеЗаполнено(...)` — для ожидаемых ситуаций.** Пустая ссылка — нормальная возможность, которую можно проверить до операции. Никакой «ошибки» нет — просто условие.

**`Попытка` — для непредвиденных сбоев.** Нельзя «заранее проверить», заблокирован ли объект другим пользователем — это становится известно только в момент попытки записи.

```
// Правильно: пустую ссылку проверяем до операции
Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
    Возврат;
КонецЕсли;

// Правильно: непредвиденный сбой перехватываем
Попытка
    Объект.Записать();
Исключение
    Сообщить(ОписаниеОшибки());
КонецПопытки;
```

> **`Если` — для ожидаемых условий, которые можно проверить. `Попытка` — для непредвиденных сбоев, которые невозможно предотвратить проверкой заранее.**

---

## 6. Что не надо делать: `Попытка` как «заглушка»

Частая ошибка — использовать `Попытка` как способ «скрыть» ошибку:

```bsl,песочница
// Плохо: ошибка скрывается, код продолжается молча
Попытка
    Объект.Записать();
Исключение
КонецПопытки; // блок Исключение пуст — ошибка проглочена
```

Пустой блок `Исключение` — антипаттерн. Ошибка происходит, но никто о ней не узнает: пользователь не получит сообщения, разработчик не увидит проблемы в журнале. Как правило, это хуже, чем получить явное сообщение об ошибке.

Минимум в блоке `Исключение` — `Сообщить(ОписаниеОшибки())`. Продвинутые варианты — записать в журнал или передать ошибку на более высокий уровень — выходят за рамки этого курса.

## 7. Канцтовары: надёжное проведение

Сравним две версии процедуры проведения документа поступления:

**Без обработки ошибок:**

```bsl,песочница
Процедура ПровестиПоступление(НомерДокумента)
    Ссылка = Документы.ПоступлениеТоваров.НайтиПоНомеру(НомерДокумента);
    Объект = Ссылка.ПолучитьОбъект();
    Объект.Записать(РежимЗаписиДокумента.Проведение);
КонецПроцедуры;
```

При пустой ссылке или сбое записи — программа упадёт с системным сообщением.

**С обработкой ошибок:**

```bsl,песочница
Процедура ПровестиПоступление(НомерДокумента)
    // Проверка входного параметра
    Если НЕ ЗначениеЗаполнено(НомерДокумента) Тогда
        Сообщить("Номер документа не указан");
        Возврат;
    КонецЕсли;

    // Поиск документа
    Ссылка = Документы.ПоступлениеТоваров.НайтиПоНомеру(НомерДокумента);
    Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
        Сообщить("Документ " + НомерДокумента + " не найден");
        Возврат;
    КонецЕсли;

    // Проведение с перехватом непредвиденных ошибок
    Объект = Ссылка.ПолучитьОбъект();
    Попытка
        Объект.Записать(РежимЗаписиДокумента.Проведение);
        Сообщить("Документ " + НомерДокумента + " проведён");
    Исключение
        Сообщить("Ошибка при проведении " + НомерДокумента + ": " + ОписаниеОшибки());
    КонецПопытки;
КонецПроцедуры;
```

Вторая версия обрабатывает три класса ситуаций: пустой параметр (ожидаемо), ненайденный документ (ожидаемо), сбой при проведении (непредвиденно).

---

## Главное в одном абзаце

`Попытка / Исключение / КонецПопытки` — конструкция для перехвата ошибок выполнения, которые нельзя предотвратить обычной проверкой: блокировка объекта другим пользователем, сбой соединения, нарушение уникальности. Если ошибка возникает в блоке `Попытка`, управление передаётся в `Исключение`. Внутри `Исключение` функция `ОписаниеОшибки()` возвращает текст ошибки. `Попытка` — не замена обычным проверкам: `Если НЕ ЗначениеЗаполнено(...)` применяется к ожидаемым ситуациям, `Попытка` — к непредвиденным сбоям. Пустой блок `Исключение` — антипаттерн: ошибка проглатывается молча.

## Упражнения

**Упражнение 1.** Что произойдёт при выполнении следующего кода, если документ с номером «РТ-000099» не существует?

```
Ссылка = Документы.РеализацияТоваров.НайтиПоНомеру("РТ-000099");
Объект = Ссылка.ПолучитьОбъект();
Объект.Записать(РежимЗаписиДокумента.Проведение);
```

---

**Упражнение 2.** Найдите антипаттерн и объясните, что здесь не так:

```bsl,песочница
Попытка
    Объект.Записать();
    Объект.Записать(РежимЗаписиДокумента.Проведение);
Исключение
КонецПопытки;
```

---

**Упражнение 3.** Добавьте в следующий код обработку ошибок: проверьте, что `Ссылка` найдена, и обработайте возможную ошибку при записи.

```
Ссылка = Справочники.Номенклатура.НайтиПоНаименованию("Ручка");
Объект = Ссылка.ПолучитьОбъект();
Объект.Цена = 20;
Объект.Записать();
```

---

**Упражнение 4.** Напишите процедуру `СоздатьТовар(Наименование, Артикул)`, которая создаёт новый элемент справочника «Номенклатура». Добавьте: проверку, что `Наименование` не пустое; `Попытка` при записи; понятное сообщение об успехе или ошибке.

---

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

`НайтиПоНомеру` вернёт пустую ссылку. Вызов `ПолучитьОбъект()` на пустой ссылке вызовет ошибку выполнения: «Значение не является значением объектного типа» или аналогичное. Программа остановится с системным сообщением об ошибке. Пользователь не получит понятного объяснения.

---

**К упражнению 2.** *Полное решение.*

Антипаттерн — пустой блок `Исключение`. Если `Записать()` или `Записать(РежимЗаписиДокумента.Проведение)` вызовет ошибку, она будет молча проглочена. Программа продолжит работу как ни в чём не бывало, хотя объект мог не сохраниться и не провестись. Кроме того, здесь два вызова `Записать` в одном блоке `Попытка` — если первый упадёт, второй выполнен не будет, что тоже может быть незаметно.

---

**К упражнению 3.** *Полное решение.*

```
Ссылка = Справочники.Номенклатура.НайтиПоНаименованию("Ручка");
Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
    Сообщить("Товар «Ручка» не найден в справочнике");
    Возврат;
КонецЕсли;

Объект = Ссылка.ПолучитьОбъект();
Объект.Цена = 20;

Попытка
    Объект.Записать();
    Сообщить("Цена обновлена");
Исключение
    Сообщить("Ошибка при сохранении: " + ОписаниеОшибки());
КонецПопытки;
```

---

**К упражнению 4.** *Полное решение.*

```bsl,песочница
Процедура СоздатьТовар(Наименование, Артикул)
    Если НЕ ЗначениеЗаполнено(Наименование) Тогда
        Сообщить("Наименование товара не указано");
        Возврат;
    КонецЕсли;

    НовыйТовар = Справочники.Номенклатура.СоздатьЭлемент();
    НовыйТовар.Наименование = Наименование;
    НовыйТовар.Артикул      = Артикул;

    Попытка
        НовыйТовар.Записать();
        Сообщить("Товар «" + Наименование + "» создан");
    Исключение
        Сообщить("Не удалось создать товар: " + ОписаниеОшибки());
    КонецПопытки;
КонецПроцедуры;
```

---

*`Попытка` защищает от непредвиденных сбоёв. Но есть и другой класс проблем, который можно и нужно предотвратить заранее — до того, как код попробует что-то сделать. Это проверки на входе: сторожевой код. § 7.3.*

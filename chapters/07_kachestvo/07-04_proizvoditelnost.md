## § 7.4. Производительность: что замедляет код

В § 7.3 мы научились писать надёжный код. Теперь — второе дополнительное измерение: производительность. В 1С она имеет особое значение: конфигурации работают с тысячами пользователей одновременно, миллионами строк в регистрах, сотнями тысяч документов. Код, который на пустой базе работает мгновенно, на боевой может тормозить минутами.

Этот параграф — не учебник по оптимизации. Это инвентарь антипаттернов: несколько устойчивых ошибок, которые встречаются снова и снова и замедляют код на порядки.

---

## 1. Почему 1С медленнее, чем кажется

Ключевое отличие 1С от обычных программ — почти всё важное хранится в базе данных, а не в оперативной памяти. Каждый вызов `ПолучитьОбъект()`, `Записать()`, `НайтиПо...()` — это обращение к базе данных. Такое обращение значительно медленнее, чем работа с переменной в памяти, — иногда в сотни и тысячи раз, в зависимости от объёма данных и нагрузки.

Поэтому главный принцип производительности в 1С:

> **Минимизировать количество обращений к базе данных. Каждый `ПолучитьОбъект()` и `Записать()` в цикле — потенциальная проблема.**

---

## 2. Антипаттерн № 1: `ПолучитьОбъект()` в цикле

**Проблема.** Каждый вызов `ПолучитьОбъект()` читает объект целиком из базы данных. При N итерациях цикла — N обращений к базе.

```
// Медленно: 1000 объектов = 1000 обращений к базе
Выборка = Справочники.Номенклатура.Выбрать();
Пока Выборка.Следующий() Цикл
    Объект = Выборка.ПолучитьОбъект(); // обращение к базе!
    Сообщить(Объект.Наименование);
КонецЦикла;
```

**Почему плохо.** Выборка уже содержит все атрибуты шапки: `Выборка.Наименование` доступно напрямую без `ПолучитьОбъект()`. Вызов `ПолучитьОбъект()` нужен только тогда, когда нужно *изменить* объект.

```
// Быстро: читаем атрибуты напрямую из выборки
Выборка = Справочники.Номенклатура.Выбрать();
Пока Выборка.Следующий() Цикл
    Сообщить(Выборка.Наименование); // атрибут уже в выборке
КонецЦикла;
```

> **Правило: `ПолучитьОбъект()` вызывать только для изменения объекта. Для чтения атрибутов — использовать выборку или ссылку напрямую.**

---

## 3. Антипаттерн № 2: `Записать()` в цикле

**Проблема.** Каждый вызов `Записать()` — транзакция с базой данных: блокировка, запись, снятие блокировки. При тысяче итераций — тысяча транзакций.

```
// Медленно: каждый товар — отдельная транзакция
Выборка = Справочники.Номенклатура.Выбрать();
Пока Выборка.Следующий() Цикл
    Объект = Выборка.ПолучитьОбъект();
    Объект.Цена = Объект.Цена * 1.1;
    Объект.Записать(); // транзакция!
КонецЦикла;
```

Здесь два антипаттерна сразу: и `ПолучитьОбъект()`, и `Записать()` в цикле.

В реальных проектах при больших объёмах данных такой код может выполняться в разы дольше, чем ожидается. Для задач массового обновления данных в 1С применяют другие инструменты — обработки, групповые операции через запросы. Для целей данного курса главное — уметь **распознать** антипаттерн при чтении.

---

## 4. Антипаттерн № 3: перебор всего без фильтра

**Проблема.** Выборка всей коллекции с фильтрацией внутри цикла перебирает больше данных, чем нужно.

```
// Медленно: перебираем все документы за все годы,
// чтобы найти только январские
Выборка = Документы.РеализацияТоваров.Выбрать();
Пока Выборка.Следующий() Цикл
    Если Выборка.Дата >= НачалоМесяца(ТекущаяДата()) Тогда
        // обработать
    КонецЕсли;
КонецЦикла;
```

При ста тысячах документов за несколько лет — все они перебираются, хотя нужны только за один месяц.

```
// Быстрее: выборка уже ограничена периодом
НачалоМес = НачалоМесяца(ТекущаяДата());
КонецМес   = КонецМесяца(ТекущаяДата());
Выборка = Документы.РеализацияТоваров.Выбрать(НачалоМес, КонецМес);
Пока Выборка.Следующий() Цикл
    // обработать
КонецЦикла;
```

> **Фильтровать как можно раньше: не перебирать лишнее, а ограничивать выборку до цикла.**

---

## 5. Антипаттерн № 4: вложенные циклы по базе данных

**Проблема.** Два вложенных цикла, каждый из которых обращается к базе данных, дают квадратичный рост нагрузки.

```
// Медленно: для каждого контрагента перебираем все документы
ВыборкаКонтрагентов = Справочники.Контрагенты.Выбрать();
Пока ВыборкаКонтрагентов.Следующий() Цикл
    ВыборкаДок = Документы.РеализацияТоваров.Выбрать();
    Пока ВыборкаДок.Следующий() Цикл
        Если ВыборкаДок.Контрагент = ВыборкаКонтрагентов.Ссылка Тогда
            // обработать
        КонецЕсли;
    КонецЦикла;
КонецЦикла;
```

При 500 контрагентах и 10 000 документах — 5 000 000 итераций. На практике такие задачи решаются языком запросов 1С, который выносится за рамки данного курса. Для чтения кода главное — видеть вложенный цикл с обращением к базе и понимать, что это узкое место.

---

## 6. Как читать код с прицелом на производительность

При чтении незнакомой процедуры стоит задать несколько вопросов:

- Есть ли `ПолучитьОбъект()` внутри цикла? Нужно ли оно там?
- Есть ли `Записать()` внутри цикла? Нельзя ли вынести?
- Перебирается ли вся коллекция там, где достаточно части?
- Есть ли вложенные циклы с обращениями к базе?

Эти вопросы не требуют глубокого знания 1С — они читаются из синтаксиса. Увидел `Выбрать()` внутри цикла по другой выборке — это сигнал.

## 7. Канцтовары: быстро и медленно

Директор «Канцтоваров» попросил повысить цену всей номенклатуры на 15%. Вот два варианта кода:

**Медленный вариант:**
```
Выборка = Справочники.Номенклатура.Выбрать();
Пока Выборка.Следующий() Цикл
    Объект = Выборка.ПолучитьОбъект(); // лишнее обращение к базе
    Объект.Цена = Объект.Цена * 1.15;
    Объект.Записать(); // транзакция в цикле
КонецЦикла;
```

При 2 000 товарах — 4 000 обращений к базе.

**Обсуждение.** Полностью избежать `ПолучитьОбъект()` и `Записать()` в цикле при массовом изменении объектов через встроенный язык невозможно — именно для таких задач в 1С рекомендуется использовать обработки или механизмы платформы, выходящие за рамки курса. Но понять, что код медленный и почему — уже ценный навык.

Что можно улучшить без языка запросов: убедиться, что `ПолучитьОбъект()` вызывается действительно для всех объектов, а не зря — например, если `Цена` уже доступна из выборки для проверки условия:

```
Выборка = Справочники.Номенклатура.Выбрать();
Пока Выборка.Следующий() Цикл
    // Если нужно менять — ПолучитьОбъект() неизбежен
    // Но если нужно только прочитать цену — выборки достаточно
    Если Выборка.Цена > 0 Тогда // читаем из выборки, без ПолучитьОбъект
        Объект = Выборка.ПолучитьОбъект();
        Объект.Цена = Объект.Цена * 1.15;
        Попытка
            Объект.Записать();
        Исключение
            Сообщить("Ошибка: " + Выборка.Наименование + " — " + ОписаниеОшибки());
        КонецПопытки;
    КонецЕсли;
КонецЦикла;
```

Здесь добавлена проверка условия через выборку (без лишнего обращения) и `Попытка` для надёжности.

---

## Главное в одном абзаце

В 1С производительность определяется прежде всего количеством обращений к базе данных. Четыре главных антипаттерна: `ПолучитьОбъект()` в цикле (каждый вызов — обращение к базе; для чтения атрибутов выборки он не нужен); `Записать()` в цикле (каждый вызов — транзакция); перебор всей коллекции там, где можно ограничить выборку; вложенные циклы с обращениями к базе. При чтении кода эти паттерны видны из синтаксиса: `ПолучитьОбъект()` или `Выбрать()` внутри цикла — сигнал на проверку. Распознать проблему производительности при чтении — уже половина решения.

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

Два антипаттерна:
1. Перебор всей выборки без фильтра по году — перебираются все документы за все годы, хотя нужны только за текущий.
2. `ПолучитьОбъект()` вызывается только для чтения `Поставщик.Наименование`, но это свойство доступно напрямую из выборки: `Выборка.Поставщик.Наименование`. `ПолучитьОбъект()` здесь лишний.

---

**К упражнению 2.** *Полное решение.*

```
НачалоГода = НачалоГода(ТекущаяДата());
КонецГода   = КонецГода(ТекущаяДата());
Выборка = Документы.ПоступлениеТоваров.Выбрать(НачалоГода, КонецГода);
Пока Выборка.Следующий() Цикл
    Сообщить(Выборка.Поставщик.Наименование); // убрали лишний ПолучитьОбъект()
КонецЦикла;
```

Устранены оба антипаттерна: выборка ограничена периодом, `ПолучитьОбъект()` убран.

---

**К упражнению 3.** *Полное решение.*

800 контрагентов × 50 000 документов = **40 000 000 итераций**. Это гарантированный тайм-аут в любой конфигурации. Задача решается через язык запросов, а не через вложенные циклы.

---

**К упражнению 4.** *Полное решение.*

Антипаттернов производительности нет. Выборка ограничена периодом (не перебирает всё). `ПолучитьОбъект()` не вызывается — только читаются атрибуты выборки. `Записать()` в цикле нет. Это правильный паттерн агрегации (§ 4.4) в применении к документам.

---

*Надёжность и производительность разобраны. Осталось третье измерение: читаемость — насколько код понятен другому человеку (или вам самим через полгода). Код, который понятен только автору в момент написания, — скрытый технический долг. § 7.5.*

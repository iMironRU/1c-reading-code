# § 7.6. Критическое чтение: читать и оценивать

В § 7.1–7.5 мы разобрали четыре измерения качества и инструменты для каждого. Теперь соберём всё вместе: критическое чтение — навык читать код с прицелом не только на понимание, но и на оценку. Этот параграф — итог Модуля 7.

---

## 1. Что значит «читать критически»

Обычное чтение кода: «что делает эта процедура?»

Критическое чтение: «что делает, зачем существует, и насколько хорошо сделано?»

Три вопроса по очереди:

1. **Что делает?** — разбор алгоритма, прогонка.
2. **Зачем существует?** — контекст, бизнес-задача (Модуль 6).
3. **Насколько хорошо?** — надёжность, производительность, читаемость (Модуль 7).

Это не три разных навыка — это три уровня одного. Опытный читатель проходит их быстро, почти автоматически.

---

## 2. Чеклист критического чтения

При анализе незнакомого фрагмента:

```текст
  Вопрос                                    Где искать
  ────────────────────────────────────────  ──────────────────────────────
  Что делает код?                           Прогонка, блок-схема
  Зачем он здесь?                           Имя процедуры, модуль, событие
  Есть ли сторожевые проверки?              Начало процедуры
  Есть ли Попытка там, где нужна?           Записать(), обращения к внешним системам
  Есть ли ПолучитьОбъект() в цикле?        Тело цикла
  Есть ли Записать() в цикле?              Тело цикла
  Понятны ли имена переменных?              Первые взгляд на каждое имя
  Нет ли магических чисел?                 Числовые литералы в условиях
  Не слишком ли длинная процедура?         Прокрутить до конца
```

Пройтись по этому чеклисту на незнакомом фрагменте — значит сформировать обоснованное мнение о его качестве.

## 3. Канцтовары: разбор реального фрагмента

Разберём процедуру критически — полностью. Это код из обработки «Канцтоваров»:

```bsl,песочница
Процедура О(Д, К)
    Если Д = 0 Тогда
        Возврат;
    КонецЕсли;
    В = Документы.РеализацияТоваров.Выбрать();
    С = 0;
    Пока В.Следующий() Цикл
        О2 = В.ПолучитьОбъект();
        Если О2.Контрагент = К И О2.СуммаДокумента > Д Тогда
            С = С + О2.СуммаДокумента;
        КонецЕсли;
    КонецЦикла;
    Сообщить(С);
КонецПроцедуры;
```

**Шаг 1 — что делает?**

Прогоняем мысленно: принимает два параметра `Д` и `К`. Если `Д = 0` — выходит. Иначе перебирает все документы «Реализация товаров», получает каждый объект, проверяет два условия: контрагент совпадает с `К` и сумма больше `Д`. Если оба — прибавляет сумму к `С`. В конце выводит `С`.

**Вероятное назначение:** подсчитать суммарный объём продаж конкретному контрагенту, превышающих порог суммы.

**Шаг 2 — зачем существует?**

Имя `О` — невозможно понять. Скорее всего из общего модуля, вызывается из отчёта или формы. Без имени и контекста это только предположение.

**Шаг 3 — оцениваем качество:**

| Критерий | Оценка | Что не так |
|---|---|---|
| Правильность | Вероятно да | Алгоритм логичен |
| Надёжность | Плохо | Нет проверки `К`; проверка `Д = 0` не ловит отрицательные значения |
| Читаемость | Очень плохо | `О`, `Д`, `К`, `В`, `О2`, `С` — все имена бессмысленны |
| Производительность | Плохо | `ПолучитьОбъект()` в цикле для чтения атрибутов |

**Шаг 4 — улучшенная версия:**

```bsl,песочница
// Суммарный объём реализации контрагенту по документам, превышающим порог
Функция РассчитатьОборотКонтрагента(ПорогСуммы, КонтрагентСсылка)
    // Сторожевые проверки
    Если НЕ ЗначениеЗаполнено(КонтрагентСсылка) Тогда
        Сообщить("Контрагент не указан");
        Возврат 0;
    КонецЕсли;

    Если ПорогСуммы <= 0 Тогда
        Сообщить("Порог суммы должен быть больше нуля");
        Возврат 0;
    КонецЕсли;

    // Подсчёт
    ОборотКонтрагента = 0;
    Выборка = Документы.РеализацияТоваров.Выбрать();
    Пока Выборка.Следующий() Цикл
        // Читаем атрибуты из выборки — без ПолучитьОбъект()
        Если Выборка.Контрагент = КонтрагентСсылка
                И Выборка.СуммаДокумента > ПорогСуммы Тогда
            ОборотКонтрагента = ОборотКонтрагента + Выборка.СуммаДокумента;
        КонецЕсли;
    КонецЦикла;

    Возврат ОборотКонтрагента;
КонецФункции;
```

Что изменилось:
- Процедура стала функцией (возвращает значение — гибче для использования).
- Имена: `О` → `РассчитатьОборотКонтрагента`, `Д` → `ПорогСуммы`, `К` → `КонтрагентСсылка`, `В` → `Выборка`, `С` → `ОборотКонтрагента`.
- Добавлены сторожевые проверки обоих параметров.
- Убран `ПолучитьОбъект()` — атрибуты читаются прямо из выборки.
- Добавлен комментарий с назначением.

## 4. Итог курса: что теперь есть в распоряжении

За девять модулей (0–7) читатель прошёл путь от «что такое данные» до «насколько хорошо написан код». Полная карта:

```текст
  Модуль 0   Данные, информация, программа — исходная точка
  Модуль 1   Лексика: переменные, типы, команды
  Модуль 2   Семантика: что значат типы, как 1С хранит данные
  Модуль 3   Структура: условия, циклы, процедуры
  Модуль 4   Паттерны: устойчивые алгоритмические приёмы
  Модуль 5   1С-идиомы: объекты, менеджеры, ссылки, записи
  Модуль 6   Контекст: документы, регистры, зачем этот код
  Модуль 7   Качество: надёжность, производительность, читаемость
```

Незнакомый фрагмент кода теперь можно читать не как шифр, а как текст на своём языке — языке 1С.

## Главное в одном абзаце

Критическое чтение — это три вопроса подряд: что делает, зачем существует, насколько хорошо сделано. Чеклист качества: есть ли сторожевые проверки, есть ли `Попытка` там, где нужна, нет ли `ПолучитьОбъект()` и `Записать()` в цикле, понятны ли имена, нет ли магических чисел. Критическое чтение — не поиск ошибок, а обоснованная оценка: где код сделан хорошо, где стоит быть осторожнее. Этот навык замыкает курс: от чтения синтаксиса — к пониманию системы — к оценке качества.

**Упражнение 4.** Финальная задача. Напишите полную, качественную функцию:

> «Найти все проведённые документы "Реализация товаров" за текущий месяц, где сумма документа превышает заданный порог, и вывести их номера и суммы. В конце вывести общее количество таких документов.»

Требования: сторожевая проверка параметра, читаемые имена, без лишних `ПолучитьОбъект()`, `Попытка` не нужна (чтение не вызывает ошибок), понятный вывод.

---

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

**Что делает:** перебирает весь справочник «Номенклатура», ищет элемент с именем, равным `Н`, и устанавливает ему цену `П`. Если найдено несколько элементов с одним именем — обновит все.

**Зачем существует:** обновить цену конкретного товара по наименованию.

**Оценка качества:**
- Надёжность: нет проверки `Н` и `П`; нет `Попытка` при записи.
- Производительность: `ПолучитьОбъект()` и `Записать()` в цикле; проще использовать `НайтиПоНаименованию()`.
- Читаемость: `УП`, `Н`, `П`, `В`, `О` — бессмысленные имена.

---

**К упражнению 2.** *Полное решение.*

```bsl,песочница
Процедура УстановитьЦенуТовара(НаименованиеТовара, НоваяЦена)
    // Сторожевые проверки
    Если НЕ ЗначениеЗаполнено(НаименованиеТовара) Тогда
        Сообщить("Наименование товара не указано");
        Возврат;
    КонецЕсли;

    Если НоваяЦена < 0 Тогда
        Сообщить("Цена не может быть отрицательной");
        Возврат;
    КонецЕсли;

    // Эффективный поиск вместо полного перебора
    Ссылка = Справочники.Номенклатура.НайтиПоНаименованию(НаименованиеТовара);
    Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
        Сообщить("Товар «" + НаименованиеТовара + "» не найден");
        Возврат;
    КонецЕсли;

    Объект = Ссылка.ПолучитьОбъект();
    Объект.Цена = НоваяЦена;
    Попытка
        Объект.Записать();
        Сообщить("Цена товара «" + НаименованиеТовара + "» обновлена до " + НоваяЦена + " руб.");
    Исключение
        Сообщить("Ошибка при сохранении: " + ОписаниеОшибки());
    КонецПопытки;
КонецПроцедуры;
```

---

**К упражнению 3.** *Полное решение.*

**Что делает:** выводит наименования всех товаров, у которых цена меньше 10 руб.

**Зачем:** скорее всего — отчёт о товарах с подозрительно низкой ценой (возможно, ошибка ввода).

**Нарушен критерий производительности:** `ПолучитьОбъект()` в цикле лишний — `Выборка.Цена` и `Выборка.Наименование` доступны напрямую. Кроме того, имя процедуры `ПроверитьОстатки` вводит в заблуждение: код не проверяет остатки, а проверяет цену.

---

**К упражнению 4.** *Полное решение.*

```bsl,песочница
Процедура ВывестиКрупныеРеализацииЗаМесяц(ПорогСуммы)
    Если ПорогСуммы <= 0 Тогда
        Сообщить("Порог суммы должен быть больше нуля");
        Возврат;
    КонецЕсли;

    НачалоМес = НачалоМесяца(ТекущаяДата());
    КонецМес   = КонецМесяца(ТекущаяДата());
    КоличествоНайдено = 0;

    Выборка = Документы.РеализацияТоваров.Выбрать(НачалоМес, КонецМес);
    Пока Выборка.Следующий() Цикл
        Если НЕ Выборка.Проведён Тогда
            Продолжить;
        КонецЕсли;

        Если Выборка.СуммаДокумента <= ПорогСуммы Тогда
            Продолжить;
        КонецЕсли;

        Сообщить(Выборка.Номер + " — " + Формат(Выборка.СуммаДокумента, "ЧДЦ=2") + " руб.");
        КоличествоНайдено = КоличествоНайдено + 1;
    КонецЦикла;

    Сообщить("Итого найдено документов: " + КоличествоНайдено);
КонецПроцедуры;
```

## Итог Модуля 7

Работающий код — это только порог. За ним три дополнительных измерения:

- **§ 7.1** — что значит хороший код: правильность, надёжность, читаемость, производительность.
- **§ 7.2** — `Попытка / Исключение`: перехват непредвиденных сбоёв.
- **§ 7.3** — защитный код: сторожевые проверки, ранний выход.
- **§ 7.4** — производительность: `ПолучитьОбъект()` и `Записать()` в цикле, перебор без фильтра.
- **§ 7.5** — читаемость: имена, комментарии, одна задача — одна процедура.
- **§ 7.6** — критическое чтение: три вопроса плюс чеклист.

Читать код, понимать его, оценивать — теперь эти действия можно соединить в единый подход.

В Модуле 8 мы сделаем шаг назад и посмотрим на всю систему целиком: как данные движутся через конфигурацию, что такое архитектура с точки зрения читателя кода.

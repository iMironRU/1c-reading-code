## § 7.3. Защитный код: проверки на входе

В § 7.2 мы научились перехватывать непредвиденные сбои с помощью `Попытка`. Но надёжность начинается раньше — до того, как код попробует что-то сделать. Хорошая процедура сначала убеждается, что условия для работы выполнены, и только потом приступает к делу. Этот стиль называют **защитным кодом** (defensive code) или программированием по контракту.

---

## 1. Принцип «упасть рано, упасть понятно»

Процедура, которая начинается без проверок, — как повар, который сначала готовит блюдо, а потом обнаруживает, что соль кончилась на последнем шаге. Лучше проверить ингредиенты до начала готовки.

В коде то же самое: если процедура получила неверные данные, лучше сообщить об этом сразу — в начале, — чем получить загадочную ошибку в середине выполнения.

> **Принцип: проверять предусловия в начале процедуры, до основной логики. Это называют сторожевым кодом (guard clauses).**

---

## 2. Сторожевые проверки: паттерн «ранний выход»

Мы уже встречали этот паттерн в § 5.5: `ЗначениеЗаполнено()` + `Возврат`. Теперь — систематически.

Структура типичной надёжной процедуры:

```
Процедура СделатьЧтоТо(Параметр1, Параметр2)
    // --- Блок проверок ---
    Если НЕ ЗначениеЗаполнено(Параметр1) Тогда
        Сообщить("Параметр1 не указан");
        Возврат;
    КонецЕсли;

    Если НЕ ЗначениеЗаполнено(Параметр2) Тогда
        Сообщить("Параметр2 не указан");
        Возврат;
    КонецЕсли;

    // --- Основная логика ---
    // Здесь мы точно знаем: оба параметра заполнены
    ...
КонецПроцедуры;
```

Каждая проверка — отдельный `Если`. Если условие нарушено — сразу `Возврат`. Это позволяет основной логике быть чистой: после блока проверок мы знаем, что все предусловия соблюдены.

---

## 3. Что проверять

В 1С типичные входные условия:

**Ссылочные реквизиты** — через `ЗначениеЗаполнено()`:
```
Если НЕ ЗначениеЗаполнено(ДокументСсылка) Тогда
    Сообщить("Документ не указан");
    Возврат;
КонецЕсли;
```

**Числовые параметры** — диапазон или знак:
```
Если КоличествоДней <= 0 Тогда
    Сообщить("Количество дней должно быть положительным");
    Возврат;
КонецЕсли;
```

**Строковые параметры** — непустая строка:
```
Если НЕ ЗначениеЗаполнено(НаименованиеТовара) Тогда
    Сообщить("Наименование не указано");
    Возврат;
КонецЕсли;
```

**Табличная часть** — не пустая:
```
Если Документ.Товары.Количество() = 0 Тогда
    Сообщить("Документ не содержит товаров");
    Возврат;
КонецЕсли;
```

---

## 4. Отказ как параметр

В обработчиках некоторых системных событий (например, `ПередЗаписью`) предусмотрен параметр `Отказ`. Установка `Отказ = Истина` — стандартный способ прервать операцию на уровне платформы, без `Возврат`:

```
Процедура ПередЗаписью(Отказ)
    Если НЕ ЗначениеЗаполнено(Контрагент) Тогда
        Сообщить("Заполните реквизит «Контрагент»");
        Отказ = Истина;
        Возврат;
    КонецЕсли;

    Если Товары.Количество() = 0 Тогда
        Сообщить("Добавьте хотя бы один товар");
        Отказ = Истина;
        Возврат;
    КонецЕсли;
КонецПроцедуры;
```

`Отказ = Истина` говорит платформе: «не продолжай запись». `Возврат` после него — хорошая практика, чтобы не выполнять оставшийся код процедуры.

---

## 5. Сторожевой код vs. вложенность

Альтернатива сторожевому коду — глубокая вложенность условий. Сравним:

**Вложенный стиль (хуже):**
```
Процедура ОбработатьДокумент(Ссылка)
    Если ЗначениеЗаполнено(Ссылка) Тогда
        Объект = Ссылка.ПолучитьОбъект();
        Если Объект.Товары.Количество() > 0 Тогда
            Если НЕ Объект.Проведён Тогда
                // основная логика
            Иначе
                Сообщить("Уже проведён");
            КонецЕсли;
        Иначе
            Сообщить("Нет товаров");
        КонецЕсли;
    Иначе
        Сообщить("Ссылка пуста");
    КонецЕсли;
КонецПроцедуры;
```

**Сторожевой стиль (лучше):**
```
Процедура ОбработатьДокумент(Ссылка)
    Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
        Сообщить("Ссылка пуста");
        Возврат;
    КонецЕсли;

    Объект = Ссылка.ПолучитьОбъект();

    Если Объект.Товары.Количество() = 0 Тогда
        Сообщить("Нет товаров");
        Возврат;
    КонецЕсли;

    Если Объект.Проведён Тогда
        Сообщить("Уже проведён");
        Возврат;
    КонецЕсли;

    // основная логика — без вложенности
КонецПроцедуры;
```

Оба варианта правильны, но второй читается линейно: каждый `Если` — одно условие, одно сообщение, один `Возврат`. Основная логика не тонет во вложенности.

> **Сторожевые проверки держат основную логику «плоской» и убирают глубокую вложенность. Код читается как список шагов, а не как матрёшка.**

---

## 6. Сообщения об ошибках должны быть полезными

Надёжный код не только останавливается при проблемах — он объясняет, что именно пошло не так. Сравните:

```
// Бесполезное сообщение
Сообщить("Ошибка");

// Полезное сообщение
Сообщить("Не указан склад в документе поступления. Заполните реквизит «Склад» и повторите попытку.");
```

Полезное сообщение отвечает на три вопроса: *что* произошло, *где* произошло (в каком реквизите или документе), *что делать*.

---

## 7. Канцтовары: надёжная процедура поступления

Вернёмся к процедуре из § 7.1 — теперь сделаем её по-настоящему надёжной:

```
Процедура ОбработатьПоступление(НомерДокумента, СкладСсылка)
    // --- Сторожевые проверки ---
    Если НЕ ЗначениеЗаполнено(НомерДокумента) Тогда
        Сообщить("Не указан номер документа поступления");
        Возврат;
    КонецЕсли;

    Если НЕ ЗначениеЗаполнено(СкладСсылка) Тогда
        Сообщить("Не указан склад для обработки");
        Возврат;
    КонецЕсли;

    // --- Поиск документа ---
    Ссылка = Документы.ПоступлениеТоваров.НайтиПоНомеру(НомерДокумента);
    Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
        Сообщить("Документ «" + НомерДокумента + "» не найден");
        Возврат;
    КонецЕсли;

    Объект = Ссылка.ПолучитьОбъект();

    // --- Проверка данных документа ---
    Если Объект.Товары.Количество() = 0 Тогда
        Сообщить("Документ «" + НомерДокумента + "» не содержит товаров");
        Возврат;
    КонецЕсли;

    Если Объект.Проведён Тогда
        Сообщить("Документ «" + НомерДокумента + "» уже проведён");
        Возврат;
    КонецЕсли;

    // --- Основная логика (все условия соблюдены) ---
    Объект.Склад = СкладСсылка;
    Попытка
        Объект.Записать(РежимЗаписиДокумента.Проведение);
        Сообщить("Документ «" + НомерДокумента + "» проведён на склад " + СкладСсылка.Наименование);
    Исключение
        Сообщить("Ошибка при проведении: " + ОписаниеОшибки());
    КонецПопытки;
КонецПроцедуры;
```

Четыре «выхода» до основной логики — это не многословность, это защита. Основная логика начинается уверенно: все предусловия выполнены.

---

## Главное в одном абзаце

Защитный код — это проверки входных условий в начале процедуры, до основной логики. Такие проверки называют сторожевыми (guard clauses): каждая проверяет одно условие и при нарушении делает ранний выход через `Возврат`. В обработчиках системных событий вместо `Возврат` используют `Отказ = Истина`. Сторожевой стиль предпочтительнее глубокой вложенности — он держит основную логику «плоской» и читаемой. Сообщения об ошибках должны отвечать на три вопроса: что произошло, где, что делать. Совместно с `Попытка / Исключение` сторожевой код формирует полную защиту: от ожидаемых плохих данных — `Если`, от непредвиденных сбоёв — `Попытка`.

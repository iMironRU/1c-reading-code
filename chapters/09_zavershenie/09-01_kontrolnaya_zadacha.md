## § 9.1. Контрольная задача: читать и пересказывать

Одна из главных целей курса — научиться брать незнакомый код и понимать, что он делает, зачем и насколько хорошо. Настало время проверить это на практике. В этом параграфе — одна процедура, около тридцати строк. Задача: прочитать её самостоятельно и дать письменный ответ по плану.

---

## 1. Как работает контрольная задача

Контрольная задача — это не тест с правильным и неправильным ответом. Это проверка того, умеет ли читатель:
- понять, **что делает** код (предметный смысл);
- объяснить, **как устроен** код (структурно);
- заметить, **что может быть лучше** (качество).

Для каждого пункта есть ориентиры ниже. Сначала — попробовать самостоятельно, не подглядывая. Потом — сравнить с разбором.

---

## 2. Задание

Прочитайте следующую функцию. Запишите ответы на все пять вопросов раздела 3 до того, как смотреть разбор.

```
&НаСервереБезКонтекста
Функция ОбновитьЦеныКатегории(КатегорияСсылка, ПроцентИзменения)

    Если НЕ ЗначениеЗаполнено(КатегорияСсылка) Тогда
        Возврат 0;
    КонецЕсли;

    Если ПроцентИзменения = 0 Тогда
        Возврат 0;
    КонецЕсли;

    Обновлено = 0;

    Выборка = Справочники.Номенклатура.Выбрать();
    Пока Выборка.Следующий() Цикл

        Если Выборка.Категория <> КатегорияСсылка Тогда
            Продолжить;
        КонецЕсли;

        Объект = Выборка.ПолучитьОбъект();
        НоваяЦена = Объект.Цена * (1 + ПроцентИзменения / 100);
        Объект.Цена = НоваяЦена;

        Попытка
            Объект.Записать();
            Обновлено = Обновлено + 1;
        Исключение
            Сообщить("Ошибка при записи " + Объект.Наименование + ": " + ОписаниеОшибки());
        КонецПопытки;

    КонецЦикла;

    Возврат Обновлено;

КонецФункции;
```

## 3. Вопросы для ответа

1. **Что делает эта функция?** Опишите одним-двумя предложениями, не используя слов «код», «переменная», «цикл». Только предметный смысл.

2. **В каком контексте она выполняется?** Как она может быть вызвана: из клиентской процедуры или только с сервера? Почему?

3. **Что происходит на каждом «этаже» функции?** Разделите функцию на смысловые блоки и кратко опишите каждый.

4. **Что возвращает функция и что это означает?** Когда она вернёт 0?

5. **Что вас настораживает в этом коде?** Найдите хотя бы одну потенциальную проблему — техническую или смысловую.

## 4. Разбор

**Вопрос 1. Что делает функция?**

Функция изменяет цену всех товаров справочника «Номенклатура», которые принадлежат заданной категории: умножает текущую цену на коэффициент, вычисленный из процента изменения. Возвращает количество успешно обновлённых записей.

*Частые ответы начинающих:*
- «Функция проходит по выборке и обновляет объекты» — это описание механизма. Попробуйте перевести «как» в «зачем»: для чего обновляет? что меняется с точки зрения бизнеса?
- «Функция считает Обновлено» — слишком технически, не объясняет, что именно считается и почему это важно.

---

**Вопрос 2. Контекст выполнения.**

`&НаСервереБезКонтекста` — серверная функция без передачи контекста формы. Может вызываться из клиентской процедуры: клиент передаёт параметры (ссылку на категорию и процент), сервер выполняет работу, возвращает результат. Именно так устроена типичная схема § 8.5.

---

**Вопрос 3. Смысловые блоки.**

```
Блок 1 (стр. 1–2): Сторожевые условия
    — проверка на незаполненную категорию
    — проверка на нулевое изменение
    → оба возвращают 0 сразу, не входя в цикл

Блок 2 (стр. 3): Инициализация счётчика
    — Обновлено = 0

Блок 3 (стр. 4–8): Основной цикл
    — перебор всей номенклатуры
    — фильтрация по категории через Продолжить
    — расчёт новой цены
    — попытка записать, подсчёт успешных

Блок 4 (стр. 9): Возврат результата
```

Функция состоит из двух ворот на входе (сторожевые условия) и основного цикла с фильтрацией и записью.

---

**Вопрос 4. Что возвращает функция.**

Функция возвращает число — количество успешно обновлённых товаров. Вернёт 0 в трёх случаях:
- категория не заполнена (первый сторожевой);
- процент изменения равен нулю (второй сторожевой);
- в справочнике нет товаров с данной категорией.

Вызывающий код может использовать это число, чтобы сообщить пользователю: «Обновлено 12 позиций».

---

**Вопрос 5. Потенциальные проблемы.**

*Производительность.* Функция перебирает **всю** номенклатуру, чтобы отфильтровать товары нужной категории. Если справочник содержит тысячи позиций, это медленно. Правильный подход — получить только нужные товары через язык запросов (§ 8.4). Это классический антипаттерн из § 7.4.

*Обработка ошибок.* При ошибке записи функция сообщает пользователю об ошибке и продолжает цикл. Вызывающий код получает частичный результат: часть товаров обновлена, часть — нет. Это может быть намеренным поведением, но требует осознанного решения — стоит ли продолжать или останавливаться при первой ошибке.

*Отрицательный процент.* Функция допускает `ПроцентИзменения < 0`, что уменьшит цены. Это может быть намеренным — но проверки нет. Если это нежелательно, нужен ещё один сторожевой блок.

*Сообщить() в серверном контексте.* Функция помечена `&НаСервереБезКонтекста`, а внутри вызывает `Сообщить()`. Поведение зависит от версии платформы и способа вызова: в некоторых случаях сообщение попадёт в очередь и будет показано пользователю при возврате управления, в других — уйдёт в журнал регистрации и не будет видно. Это стоит учитывать при отладке.

## 5. Как оценить свой результат

**Хороший ответ на вопрос 1** — предметный, без технических терминов. «Обновляет цены товаров категории» — достаточно. «Проходит по Выборка.Следующий()» — ответ уровня синтаксиса: вы видите код, но ещё не поднялись до смысла.

**Хороший ответ на вопрос 3** — выделены именно смысловые блоки, не отдельные строки. Не «присваивает НоваяЦена», а «рассчитывает новую цену».

**Хороший ответ на вопрос 5** — находит хотя бы одну проблему. Производительность — самая очевидная. Все три проблемы — отлично.

> **Если вы ответили на все пять вопросов разумно и без подсказок — курс выполнил свою задачу.**

## Главное в одном абзаце

Контрольная задача — это проверка трёх умений сразу: понять предметный смысл кода, описать его структуру и оценить качество. В разобранной функции: два сторожевых условия на входе, основной цикл с фильтрацией по категории, обработка ошибок через Попытка/Исключение, возврат счётчика. Слабое место — перебор всей номенклатуры вместо целевого запроса. Умение замечать такие места — и есть то, чему учил курс.

## Ответы к дополнительным заданиям

**К заданию 1.** Нужно вынести `Попытка/Исключение` так, чтобы при ошибке выходить из цикла. Один из вариантов — добавить переменную `ЕстьОшибка` и проверять её после блока `Исключение`:

```
ЕстьОшибка = Ложь;
...
Исключение
    Сообщить("Ошибка при записи " + Объект.Наименование + ": " + ОписаниеОшибки());
    ЕстьОшибка = Истина;
КонецПопытки;

Если ЕстьОшибка Тогда
    Прервать;
КонецЕсли;
```

**К заданию 2.** Обоснование: снижение цены более чем на 50% — вероятно, ошибка ввода. Сторожевой блок защищает от случайного обнуления цен:

```
Если ПроцентИзменения < -50 Тогда
    Возврат 0;
КонецЕсли;
```

Решение намеренное: если нужно снизить на 60%, это должно быть явно запрошено или функцию нужно доработать.

## § 8.2. Где хранится логика: модули и их назначение

В § 6.1 мы впервые встретились с модулями: код живёт в них, а не «в воздухе». Мы познакомились с тремя видами — форма, объект, общий. Теперь — систематически: сколько видов модулей существует, что хранится в каждом, и как, читая процедуру, понять, откуда она.

---

## 1. Модуль как контейнер кода

Модуль — это текстовый файл с кодом, привязанный к конкретному объекту конфигурации или стоящий отдельно. Один объект — один или несколько модулей. Они различаются по назначению и по тому, *когда* и *где* их выполняет платформа.

Главный вопрос при чтении любой процедуры: «в каком модуле это живёт?»

---

## 2. Модуль объекта

Привязан к конкретному объекту — документу или справочнику. Содержит обработчики событий жизненного цикла.

Типичное содержимое:
- `ОбработкаПроведения` — при проведении документа (§ 8.1)
- `ПередЗаписью` — до записи объекта (§ 7.3)
- `ПриЗаписи` — после записи
- `ОбработкаУдаления` — при удалении

Этот модуль выполняется **на сервере** — там, где находится база данных.

> **Модуль объекта = «жизненный цикл объекта». Здесь описывается, что происходит при создании, записи и проведении.**

---

## 3. Модуль формы

Привязан к конкретной форме объекта. Содержит обработчики событий интерфейса: нажатие кнопки, изменение поля, открытие формы.

Типичное содержимое:
- `КнопкаПровестиНажатие` — нажатие кнопки в форме
- `НоменклатураПриИзменении` — изменение реквизита формы
- `ПриОткрытии` — при открытии формы пользователем

По умолчанию работает **на клиенте** (там, где находится пользователь), но отдельные процедуры могут быть явно помечены как серверные — об этом в § 8.5.

---

## 4. Модуль менеджера

Есть у каждого объекта конфигурации, но привязан не к экземпляру (конкретному документу), а к типу в целом. Через него вызываются «классовые» методы — операции, не требующие конкретного объекта.

Именно здесь определены методы поиска: `НайтиПоНомеру`, `НайтиПоНаименованию`, `НайтиПоКоду`.

```
// Это вызов метода модуля менеджера документа:
Ссылка = Документы.ПоступлениеТоваров.НайтиПоНомеру("ПТ-0001");
//                                    ─────────────────────────
//                                    метод определён в модуле менеджера
```

> **Модуль менеджера = «операции на уровне типа». Поиск, создание, получение списка — всё это живёт здесь.**

---

## 5. Общий модуль

Не привязан ни к одному объекту — это библиотека разделяемых процедур и функций. Любой другой код может их вызывать.

Типичное назначение:
- Вспомогательные расчёты, нужные многим объектам
- Вывод и форматирование сообщений
- Стандартные проверки и обработка ошибок

У общего модуля есть важное свойство: он может работать на клиенте, на сервере или на обоих одновременно — это задаётся в настройках самого модуля. Подробнее — в § 8.5.

---

## 6. Сводная карта

```
Тип модуля          Привязан к          Типичное содержимое
──────────────────  ──────────────────  ─────────────────────────────────
Модуль объекта      Документ/Справ.     ОбработкаПроведения, ПередЗаписью
Модуль формы        Форма объекта       КнопкаНажатие, ПолеПриИзменении
Модуль менеджера    Тип объекта         НайтиПо..., СоздатьДокумент
Общий модуль        (не привязан)       Вспомогательные процедуры и функции
```

Есть и другие виды — модуль приложения, модуль сеанса, модуль расширения — но они выходят за рамки этого курса.

---

## 7. Канцтовары: откуда вызывается код

Руководитель нажимает кнопку «Провести» в форме документа «ПоступлениеТоваров». Проследим путь:

```
Кнопка «Провести» нажата
        │
        ▼  модуль формы
КнопкаПровестиНажатие()
        │
        ▼  платформа вызывает обработчик объекта
ОбработкаПроведения()   — модуль объекта
        │
        ▼  если нужна общая логика
ОбщийМодуль.ПроверитьДокумент()   — общий модуль
```

Каждый шаг — другой модуль. Понимание этой карты помогает ориентироваться в большой конфигурации.

---

## Главное в одном абзаце

Код в 1С хранится в модулях — каждый привязан к своей роли. Модуль объекта содержит обработчики жизненного цикла (проведение, запись, удаление) и выполняется на сервере. Модуль формы содержит логику интерфейса (нажатие кнопок, изменение полей) и по умолчанию работает на клиенте. Модуль менеджера хранит «классовые» методы — поиск, создание, получение по реквизиту; именно там определены `НайтиПоНомеру` и им подобные. Общий модуль — библиотека разделяемых процедур, доступная любому объекту. Читая незнакомую процедуру, первый вопрос: «в каком модуле она живёт?» — это сразу задаёт контекст её назначения.

## Контрольные вопросы

1. Какие четыре вида модулей рассмотрены в параграфе и за что каждый отвечает?
2. Где выполняется модуль объекта — на клиенте или на сервере?
3. Чем модуль менеджера отличается от модуля объекта?
4. Зачем нужен общий модуль, если можно писать код прямо в модуле формы?
5. В каком модуле определён метод `НайтиПоНомеру`?

## Упражнения

**Упражнение 1.** Определите, в каком модуле скорее всего живёт каждая из следующих процедур:

(а) `КнопкаСохранитьНажатие`  
(б) `ОбработкаПроведения`  
(в) `НайтиПоИНН`  
(г) `РассчитатьСуммуСкидки`  

---

**Упражнение 2.** Объясните, почему следующие три строки указывают на разные модули одного объекта, а не на один и тот же:

```
ПоступлениеТоваров — МодульФормы
ПоступлениеТоваров — МодульОбъекта
ПоступлениеТоваров — МодульМенеджера
```

---

**Упражнение 3.** В каком модуле нужно написать обработчик, если нужно:

(а) Реагировать на изменение реквизита «Контрагент» в форме документа.  
(б) Заблокировать запись документа без заполненного склада.  
(в) Найти документ по произвольному реквизиту «НомерЗаказа».  

---

**Упражнение 4.** Прочитайте следующий вызов и определите: метод какого модуля вызывается на каждой строке?

```
// Строка 1
Ссылка = Справочники.Контрагенты.НайтиПоНаименованию("ООО Степлер");

// Строка 2
Объект = Ссылка.ПолучитьОбъект();

// Строки 3-4
Объект.ИНН = "7702123456";
Объект.Записать();
```

---

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

(а) `КнопкаСохранитьНажатие` — **модуль формы** (обработчик нажатия кнопки в интерфейсе).  
(б) `ОбработкаПроведения` — **модуль объекта** (событие жизненного цикла документа, выполняется на сервере).  
(в) `НайтиПоИНН` — **модуль менеджера** (поиск по реквизиту — операция уровня типа, не требует конкретного экземпляра).  
(г) `РассчитатьСуммуСкидки` — скорее всего **общий модуль** (расчётная функция, которая может понадобиться разным объектам).

---

**К упражнению 2.** *Полное решение.*

Все три модуля принадлежат объекту «ПоступлениеТоваров», но выполняют разные роли:
- `МодульФормы` — код интерфейса конкретной формы, работает на клиенте.
- `МодульОбъекта` — обработчики жизненного цикла экземпляра, работает на сервере.
- `МодульМенеджера` — операции уровня типа (поиск, создание), работает на сервере.

Один объект — три разных «точки входа» с разными обязанностями.

---

**К упражнению 3.** *Полное решение.*

(а) Изменение реквизита «Контрагент» в форме — **модуль формы** (событие интерфейса).  
(б) Блокировка записи без склада — **модуль объекта**, обработчик `ПередЗаписью` с `Отказ = Истина` (§ 7.3).  
(в) Поиск по реквизиту «НомерЗаказа» — **модуль менеджера** (или написать вызов стандартного метода менеджера с передачей нужного параметра).

---

**К упражнению 4.** *Полное решение.*

```
// Строка 1: НайтиПоНаименованию — метод модуля менеджера справочника
Ссылка = Справочники.Контрагенты.НайтиПоНаименованию("ООО Степлер");

// Строка 2: ПолучитьОбъект — метод ссылки, реализован платформой;
// загружает объект из базы данных
Объект = Ссылка.ПолучитьОбъект();

// Строки 3-4: присваивание реквизита и Записать() — работа с объектом;
// Записать() — встроенный метод платформы; при его вызове платформа
// обращается к обработчикам ПередЗаписью / ПриЗаписи из модуля объекта
Объект.ИНН = "7702123456";
Объект.Записать();
```

---

*Теперь мы знаем, где живёт код. Осталось понять, из чего вообще состоит конфигурация — какие типы объектов существуют. § 8.3.*

# § 8.1. Куда уходят данные после нажатия «Провести»

В [§ 6.3](../06_kontekst/06-03_zhiznennyy_tsikl_dokumenta.md) мы рассмотрели жизненный цикл документа и узнали, что проведение — это не просто сохранение: оно фиксирует событие и создаёт движения в регистрах. В [§ 6.4](../06_kontekst/06-04_registry.md) мы познакомились с регистрами накопления — хранилищами накопленного состояния. Теперь посмотрим на весь путь изнутри: от нажатия кнопки «Провести» до строки в регистре.

---

## 1. Проведение глазами системы

Когда пользователь нажимает «Провести», платформа выполняет цепочку шагов:

```
Пользователь нажал «Провести»
        │
        ▼
Платформа блокирует объект
        │
        ▼
Платформа вызывает ОбработкаПроведения()
        │  (процедура в модуле объекта документа)
        ▼
Обработчик создаёт записи в объекте Движения
        │
        ▼
Платформа записывает движения в таблицы регистров
        │
        ▼
Платформа устанавливает флаг «Проведён» и сохраняет документ
```

Ключевое место — обработчик `ОбработкаПроведения`. Именно там программист описывает, *что именно изменилось в системе* в результате этого события.

---

## 2. Обработчик ОбработкаПроведения

Это процедура в модуле объекта документа с фиксированной сигнатурой:

```
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
    // Здесь создаются движения в регистрах
КонецПроцедуры;
```

Параметры:
- `Отказ` — установить в `Истина`, чтобы отменить проведение. Сторожевой код из [§ 7.3](../07_kachestvo/07-03_zashchitnyy_kod.md) применяется здесь напрямую.
- `РежимПроведения` — оперативное проведение (в реальном времени) или неоперативное (задним числом). Влияет на контроль остатков — подробности выходят за рамки курса.

Внутри обработчика доступен специальный объект — `Движения`.

---

## 3. Объект Движения

`Движения` — это коллекция наборов записей по каждому регистру, к которому обращается документ:

```
Движения
  ├── Движения.ТоварыНаСкладах       — набор записей регистра «ТоварыНаСкладах»
  └── Движения.ВзаиморасчётыСКлиентами  — набор записей другого регистра
```

Чтобы создать движение, нужно три шага:
1. Включить запись набора: `Движения.НазваниеРегистра.Записывать = Истина`
2. Добавить строку: `Движение = Движения.НазваниеРегистра.Добавить()`
3. Заполнить поля строки.

> **`Движения` — объект, доступный в `ОбработкаПроведения`. Через него программист описывает, какие строки добавляются в регистры при проведении документа.**

---

## 4. Синтаксис создания движения

```
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
    // Шаг 1: указываем, что регистр нужно обновить
    Движения.ТоварыНаСкладах.Записывать = Истина;

    // Шаг 2-3: перебираем строки ТЧ, добавляем строку, заполняем поля
    Для каждого Строка Из Товары Цикл
        Движение = Движения.ТоварыНаСкладах.Добавить();
        Движение.ВидДвижения  = ВидДвиженияНакопления.Приход;
        Движение.Период       = Дата;
        Движение.Номенклатура = Строка.Номенклатура;
        Движение.Количество   = Строка.Количество;
    КонецЦикла;
КонецПроцедуры;
```

Что значит каждая строка:

| Строка | Что делает |
|--------|------------|
| `Записывать = Истина` | Говорит платформе: «этот регистр нужно сохранить» |
| `Для каждого Строка Из Товары` | Перебор табличной части документа |
| `.Добавить()` | Создаёт пустую строку в наборе записей |
| `ВидДвижения = Приход` | Приход увеличивает остаток ([§ 6.4](../06_kontekst/06-04_registry.md)) |
| `Период = Дата` | Дата документа — дата движения |
| `Номенклатура = Строка.Номенклатура` | Измерение — «что» |
| `Количество = Строка.Количество` | Ресурс — «сколько» |

---

## 5. Что происходит после обработчика

После завершения `ОбработкаПроведения` платформа записывает в базу данных:
- Строки набора `Движения.ТоварыНаСкладах` — в таблицу регистра.
- Сам документ — с установленным флагом `Проведён`.

После этого виртуальная таблица остатков регистра учитывает только что добавленные движения при выполнении запроса ([§ 6.4](../06_kontekst/06-04_registry.md)).

> **Как правило, проведение включает вызов `ОбработкаПроведения` и запись движений в регистры. Именно движения — основной результат проведения, сохраняемый в системе.**

---

## 6. Как читать код проведения

Встречая `ОбработкаПроведения` в чужом коде, задайте три вопроса:

1. **В какие регистры пишет документ?** — по именам `Движения.НазваниеРегистра`.
2. **Какие поля заполняются?** — по строкам `Движение.ИмяПоля = ...`.
3. **Есть ли условия на движения?** — по `Если` внутри цикла.

Увидев `Движения.ВзаиморасчётыСКонтрагентами` — понимаем, что документ влияет на расчёты. Увидев `ВидДвижения = Расход` — что что-то списывается.

---

## 7. Канцтовары: реализация списывает товар

Документ «Реализация товаров» уменьшает остаток на складе. Поэтому в `ОбработкаПроведения` создаётся движение с видом «Расход»:

```
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
    Движения.ТоварыНаСкладах.Записывать = Истина;

    Для каждого Строка Из Товары Цикл
        Движение = Движения.ТоварыНаСкладах.Добавить();
        Движение.ВидДвижения  = ВидДвиженияНакопления.Расход;
        Движение.Период       = Дата;
        Движение.Номенклатура = Строка.Номенклатура;
        Движение.Количество   = Строка.Количество;
    КонецЦикла;
КонецПроцедуры;
```

Поступление даёт «Приход», реализация — «Расход». Остаток = сумма приходов − сумма расходов. Так работает регистр накопления.

---

## Главное в одном абзаце

Когда пользователь нажимает «Провести», платформа вызывает обработчик `ОбработкаПроведения` — процедуру в модуле объекта документа. Внутри неё программист через объект `Движения` создаёт записи в регистрах: `Движения.НазваниеРегистра.Записывать = Истина` включает запись набора; `.Добавить()` создаёт новую строку; поля строки (вид движения, период, измерения, ресурсы) заполняются из данных документа. После выхода из обработчика платформа записывает движения в базу и устанавливает флаг «Проведён». Именно движения — то, что остаётся в системе после события: поступление создаёт «Приход», реализация — «Расход», остатки вычисляются как разница.

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

Документ при проведении записывает в регистр взаиморасчётов движения вида «Приход». Для каждой строки табличной части создаётся запись: контрагент из шапки документа, сумма из строки. Вид движения «Приход» означает увеличение задолженности — скорее всего, это документ продажи: покупатель нам должен.

---

**К упражнению 2.** *Полное решение.*

**Приход.** Регистр `ТоварыНаСкладах` накапливает остаток товаров. Продажа уменьшает остаток («Расход»). Возврат возвращает товар на склад — это увеличение остатка, то есть «Приход». Остаток = Приходы − Расходы.

---

**К упражнению 3.** *Полное решение.*

Отсутствует строка `Движения.ТоварыНаСкладах.Записывать = Истина`. Без неё платформа не записывает набор в базу данных, даже если строки были добавлены: они остаются в памяти и не попадают в таблицу регистра.

Исправление — добавить перед циклом:
```
Движения.ТоварыНаСкладах.Записывать = Истина;
```

---

**К упражнению 4.** *Полное решение.*

| Поле | Вид | Обоснование |
|------|-----|-------------|
| `Контрагент` | Измерение | Определяет «кто» — разрез получения остатков |
| `Сумма` | Ресурс | Числовое значение, которое суммируется |
| `Склад` | Измерение | Определяет «где» — разрез по местам хранения |
| `Количество` | Ресурс | Числовое значение, которое накапливается |
| `Номенклатура` | Измерение | Определяет «что» — разрез по товарам |
| `Валюта` | Измерение | Определяет «в чём» — разрез по валютам |

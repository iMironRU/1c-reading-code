# § 8.5. Директивы и области

В [§ 8.4](08-04_baryery.md) мы увидели, что код в управляемом приложении 1С выполняется в двух контекстах — клиент и сервер, и что их различие отражено прямо в тексте кода специальными метками. Теперь — как именно: директивы компиляции — это аннотации перед процедурами, указывающие платформе, где процедура выполняется. Встретив их в незнакомом коде, читатель должен понимать их смысл.

---

## 1. Зачем нужны директивы

В управляемом приложении платформа компилирует один и тот же модуль дважды: отдельно для клиента и отдельно для сервера. Чтобы указать, какой контекст нужен конкретной процедуре, перед ней ставится директива.

Директива — не комментарий. Платформа читает её при компиляции и решает, куда включать код.

---

## 2. Основные директивы

**`&НаКлиенте`** — процедура выполняется у пользователя. Имеет доступ к интерфейсу, но не может напрямую обращаться к базе данных — все данные получает через серверные вызовы.

```
&НаКлиенте
Процедура КнопкаОКНажатие(Команда)
    ОчиститьСообщения();
    ЗагрузитьДанныеНаСервере(); // вызов серверной процедуры
КонецПроцедуры;
```

**`&НаСервере`** — процедура выполняется на сервере. Имеет полный доступ к базе, но не к интерфейсу.

```
&НаСервере
Процедура ЗагрузитьДанныеНаСервере()
    Выборка = Справочники.Номенклатура.Выбрать();
    // ... работа с базой
КонецПроцедуры;
```

**`&НаСервереБезКонтекста`** — серверная процедура без доступа к данным формы. Принимает всё через параметры. Предпочтительна, когда серверной функции не нужна форма — это экономит передачу данных между клиентом и сервером.

```
&НаСервереБезКонтекста
Функция ПолучитьЦенуНаСервере(НоменклатураСсылка)
    Возврат НоменклатураСсылка.Цена;
КонецФункции;
```

> **Директива перед процедурой — не комментарий. Она указывает платформе, в какой среде компилировать и выполнять этот код.**

---

## 3. Типичная схема: клиент вызывает сервер

В управляемом приложении типичная схема такова: клиентская процедура (обработчик кнопки) вызывает серверную функцию для работы с данными:

```
&НаКлиенте
Процедура КнопкаПровестиНажатие(Команда)
    // Клиент передаёт ссылку на сервер и получает результат
    Успех = ПровестиДокументНаСервере(Объект.Ссылка);
    Если НЕ Успех Тогда
        Сообщить("Не удалось провести документ");
    КонецЕсли;
КонецПроцедуры;

&НаСервереБезКонтекста
Функция ПровестиДокументНаСервере(ДокументСсылка)
    Объект = ДокументСсылка.ПолучитьОбъект();
    Попытка
        Объект.Записать(РежимЗаписиДокумента.Проведение);
        Возврат Истина;
    Исключение
        Сообщить(ОписаниеОшибки());
        Возврат Ложь;
    КонецПопытки;
КонецФункции;
```

Клиентская процедура отвечает за интерфейс, серверная — за работу с данными. Обе существуют в одном модуле формы, но выполняются в разных местах.

---

## 4. Препроцессорные директивы

Кроме аннотаций контекста, в 1С есть препроцессорные директивы — они управляют условной компиляцией:

```
#Если Клиент Тогда
    // Этот блок включается только в клиентскую сборку
    Сообщить("Работаю на клиенте");
#КонецЕсли
```

Препроцессорные директивы начинаются с `#` и обрабатываются до компиляции — на этапе, когда платформа решает, какой код вообще будет включён в сборку. Встречаются реже, чем `&НаКлиенте` / `&НаСервере`, но знать об их существовании полезно: блок `#Если ... #КонецЕсли` может «скрывать» код, который выполняется только в определённом контексте.

---

## 5. Области

Области — ещё один элемент, часто встречающийся в аккуратно написанном коде:

```
#Область ОбработчикиСобытийФормы

&НаКлиенте
Процедура ПриОткрытии(Отказ)
    ...
КонецПроцедуры;

#КонецОбласти

#Область СлужебныеПроцедуры

&НаСервереБезКонтекста
Функция ПолучитьДанные(Параметр)
    ...
КонецФункции;

#КонецОбласти
```

Области — визуальный инструмент: группировка кода, которую можно свернуть в редакторе конфигуратора. Как правило, на выполнение программы они не влияют. Но в хорошо структурированных модулях дают быстрый ориентир: где обработчики событий, где служебные процедуры.

> **`#Область ... #КонецОбласти` — группировка кода для удобства чтения. Как правило, на поведение программы не влияет.**

---

## 6. Как читать код с директивами

При встрече с директивами:
- `&НаКлиенте` — процедура работает у пользователя. Интерфейс — да, база — нет.
- `&НаСервере` — процедура работает с базой. Интерфейс — нет.
- `&НаСервереБезКонтекста` — серверная, но без формы. Чище и быстрее.
- `#Область` — просто разделитель. Смотрите на содержимое, не на название.
- `#Если ... #КонецЕсли` — условная компиляция; один из блоков может отсутствовать в сборке.

Цепочка вызовов обычно чередует контексты: кнопка (клиент) → серверная функция → возврат результата (клиент).

---

## Главное в одном абзаце

В управляемом приложении 1С каждая процедура может быть помечена директивой контекста: `&НаКлиенте` (работает у пользователя, имеет доступ к интерфейсу), `&НаСервере` (работает с базой данных) или `&НаСервереБезКонтекста` (серверная без передачи состояния формы — предпочтительна, когда форма не нужна). Типичная схема: клиентская процедура-обработчик вызывает серверную функцию для работы с данными и получает результат. Препроцессорные директивы `#Если` управляют условной компиляцией. Области `#Область ... #КонецОбласти` — визуальная группировка кода без влияния на выполнение. При чтении кода директивы — важный ориентир: они сразу говорят, в каком контексте выполняется каждая процедура.

**Упражнение 1.** Определите контекст каждой процедуры и что она может делать:

```
&НаСервере
Процедура ЗаполнитьТаблицу()
    ...
КонецПроцедуры;

&НаКлиенте
Процедура ТаблицаВыбор(ТекущиеДанные, Стандартная)
    ...
КонецПроцедуры;

&НаСервереБезКонтекста
Функция ПолучитьОстатки(НоменклатураСсылка)
    ...
КонецФункции;
```

---

**Упражнение 2.** Можно ли вызвать следующую функцию из клиентской процедуры? Объясните.

```
&НаСервере
Функция ПолучитьСписокКонтрагентов()
    Результат = Новый СписокЗначений;
    Выборка = Справочники.Контрагенты.Выбрать();
    Пока Выборка.Следующий() Цикл
        Результат.Добавить(Выборка.Ссылка, Выборка.Наименование);
    КонецЦикла;
    Возврат Результат;
КонецФункции;
```

---

**Упражнение 3.** Перепишите следующую клиентскую процедуру корректно, вынесев работу с базой на сервер:

```
&НаКлиенте
Процедура КнопкаНажатие()
    Ссылка = Справочники.Контрагенты.НайтиПоНаименованию("ООО Степлер");
    Сообщить(Ссылка.ИНН);
КонецПроцедуры;
```

---

**Упражнение 4.** Найдите в следующем модуле все директивы и определите, что они означают:

```
#Область ОбработчикиСобытий

&НаКлиенте
Процедура ПриОткрытии(Отказ)
    ОбновитьЗаголовок();
КонецПроцедуры;

&НаКлиенте
Процедура КнопкаОКНажатие(Команда)
    ЗаписатьДанныеНаСервере();
КонецПроцедуры;

#КонецОбласти

#Область СлужебныеПроцедуры

&НаСервере
Процедура ЗаписатьДанныеНаСервере()
    ЭтотОбъект.Записать();
КонецПроцедуры;

#КонецОбласти
```

---

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

- `ЗаполнитьТаблицу` — **сервер**: может читать базу данных, заполнять таблицу значений; нет доступа к форме.
- `ТаблицаВыбор` — **клиент**: обработчик события интерфейса (выбор строки таблицы); может работать с формой, но не с базой напрямую.
- `ПолучитьОстатки` — **сервер без контекста формы**: принимает ссылку параметром, возвращает данные; чистая и быстрая серверная функция.

---

**К упражнению 2.** *Полное решение.*

Да. Серверные функции (`&НаСервере`) можно вызывать из клиентских процедур — платформа организует вызов автоматически: клиент передаёт управление на сервер, сервер выполняет функцию и возвращает результат клиенту. Именно это и есть стандартная схема взаимодействия.

---

**К упражнению 3.** *Полное решение.*

```
&НаКлиенте
Процедура КнопкаНажатие()
    ИНН = ПолучитьИНН_НаСервере("ООО Степлер");
    Сообщить(ИНН);
КонецПроцедуры;

&НаСервереБезКонтекста
Функция ПолучитьИНН_НаСервере(Наименование)
    Ссылка = Справочники.Контрагенты.НайтиПоНаименованию(Наименование);
    Если НЕ ЗначениеЗаполнено(Ссылка) Тогда
        Возврат "";
    КонецЕсли;
    Возврат Ссылка.ИНН;
КонецФункции;
```

---

**К упражнению 4.** *Полное решение.*

- `#Область ОбработчикиСобытий` / `#КонецОбласти` — визуальная группировка обработчиков; на выполнение не влияет.
- `&НаКлиенте` (перед `ПриОткрытии`) — процедура работает на клиенте, вызывается при открытии формы.
- `&НаКлиенте` (перед `КнопкаОКНажатие`) — обработчик кнопки на клиенте.
- `#Область СлужебныеПроцедуры` / `#КонецОбласти` — визуальная группировка служебного кода.
- `&НаСервере` (перед `ЗаписатьДанныеНаСервере`) — серверная процедура, имеет доступ к форме через `ЭтотОбъект`, вызывает запись на сервере.

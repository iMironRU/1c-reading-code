## § 8.3. Карта объектов конфигурации

В § 8.2 мы разобрались с модулями — где хранится код. Теперь поднимемся уровнем выше и посмотрим на саму конфигурацию: из каких типов объектов она состоит. Справочники, документы и регистры мы уже знаем. Но это не полный список.

---

## 1. Конфигурация — это дерево объектов

В конфигурации 1С каждый объект принадлежит определённому типу. Тип определяет:
- **Что хранит** объект
- **Какие события** у него есть
- **Как с ним работает** платформа

Зная тип объекта, читатель сразу понимает его роль в системе — без просмотра всего кода.

---

## 2. Сущности

**Справочники** — уже знакомы. Хранят относительно постоянные объекты предметной области: товары, контрагенты, сотрудники, склады. Каждый элемент — отдельная запись с реквизитами.

**Константы** — одно значение, действующее для всей системы. Например: «Наименование организации», «Ставка НДС по умолчанию». Меняются редко; доступны из любого места кода.

**Перечисления** — фиксированный набор значений, заданный при разработке. Нельзя добавить значение без изменения конфигурации. Используются для статусов, видов, категорий.

```
// Пример использования перечисления:
Если Заказ.Статус = Перечисления.СтатусыЗаказов.ВРаботе Тогда
    ...
КонецЕсли;
```

**Планы видов характеристик** — механизм «гибких реквизитов»: позволяют добавлять дополнительные характеристики к объектам динамически, без изменения структуры базы. Используются в типовых конфигурациях для учёта особенностей товаров, клиентов и т.д.

---

## 3. События

**Документы** — уже знакомы. Фиксируют бизнес-события: Поступление, Реализация, Оплата. Имеют жизненный цикл, могут создавать движения в регистрах.

**Журналы документов** — группируют документы разных типов в одном списке. Например, журнал «Расчёты с контрагентами» объединяет поступления, реализации и оплаты — чтобы пользователь видел всю историю по контрагенту в одном месте.

---

## 4. Накопленное состояние

Четыре вида регистров — уже упоминались в § 6.4, теперь на карте:

```
Регистры накопления  — остатки и обороты (товары на складе, деньги)
Регистры сведений    — история значений (курсы валют, цены товаров)
Регистры бухгалтерии — бухгалтерский учёт (дебет/кредит, счета)
Регистры расчётов    — периодические расчёты (начисления зарплаты)
```

В большинстве прикладных задач чаще всего встречаются регистры накопления и регистры сведений.

---

## 5. Инструменты обработки и вывода

**Отчёты** — формируют представление данных в ответ на запрос пользователя. Выбрал период, нажал «Сформировать» — получил таблицу. Обычно используют язык запросов (§ 8.4) и систему компоновки данных.

**Обработки** — самостоятельные программы без фиксированного объекта данных. Запускаются вручную или из меню. Например: «Массовое изменение цен», «Выгрузка данных».

**Регламентные задания** — задачи, которые платформа выполняет автоматически по расписанию: каждый час, раз в день, раз в неделю.

---

## 6. Служебные объекты

Конфигурация включает и служебные объекты, которые выходят за рамки хранения или обработки данных. Они здесь перечислены для ориентира — не изучаются в этом курсе, но встречаются в реальных конфигурациях.

**Планы обмена** — описывают, как синхронизировать данные между двумя базами 1С или с внешней системой.

**Бизнес-процессы и задачи** — механизм маршрутизации задач между сотрудниками. Встречается в некоторых типовых конфигурациях.

**Роли** — описывают права доступа: кто что может читать, записывать, удалять. Не содержат кода, но влияют на выполнение.

---

## 7. Карта одним взглядом

```
Тип объекта                 Вопрос, на который отвечает
──────────────────────────  ─────────────────────────────────────
Справочник                  Кто? Что? (сущности)
Константа                   Какова настройка системы?
Перечисление                Какие значения фиксированы?
Документ                    Что произошло? (событие)
Журнал документов           Где смотреть историю по теме?
Регистр накопления          Сколько осталось / обернулось?
Регистр сведений            Каким было значение в момент времени?
Регистр бухгалтерии         Каков баланс по счёту?
Регистр расчётов            Каков расчёт за период?
Отчёт                       Какой ответ на вопрос пользователя?
Обработка                   Как выполнить разовую задачу?
Регламентное задание        Что делать автоматически по расписанию?
```

---

## Главное в одном абзаце

Конфигурация 1С — это дерево объектов разных типов, каждый из которых отвечает за свой класс задач. Справочники хранят сущности, константы — системные настройки, перечисления — фиксированные наборы значений. Документы фиксируют события и создают движения в регистрах. Четыре вида регистров накапливают состояние по-разному: накопления — остатки и обороты, сведений — историю значений, бухгалтерии — бухгалтерский учёт, расчётов — периодические начисления. Отчёты отвечают на вопросы пользователя, обработки решают разовые задачи, регламентные задания работают по расписанию. Зная, к какому типу принадлежит объект, читатель сразу получает ориентир — и понимает, что там искать.

## Контрольные вопросы

1. Чем справочник отличается от перечисления?
2. Что такое константа? Приведите пример.
3. В чём разница между регистром накопления и регистром сведений?
4. Чем отчёт отличается от обработки по назначению?
5. Для чего нужны регламентные задания?

## Упражнения

**Упражнение 1.** Определите, объект какого типа лучше всего подходит для каждой задачи:

(а) Хранить список валют.  
(б) Фиксировать факт оплаты клиентом.  
(в) Отслеживать курс доллара на каждый день.  
(г) Показывать руководителю выручку за месяц.  
(д) Автоматически закрывать просроченные заказы.  

---

**Упражнение 2.** Какой вид регистра нужен для каждой задачи?

(а) Знать текущий остаток товара на складе.  
(б) Знать, какую цену имел товар три месяца назад.  
(в) Вести бухгалтерский учёт по счетам.  

---

**Упражнение 3.** Найдите в следующем фрагменте кода обращения к объектам трёх разных типов и назовите их типы:

```
Курс = РегистрыСведений.КурсыВалют.ПолучитьПоследнее(ТекущаяДата()).Курс;
Если Заказ.Статус = Перечисления.СтатусыЗаказов.Закрыт Тогда
    Ссылка = Справочники.Валюты.НайтиПоНаименованию("USD");
КонецЕсли;
```

---

**Упражнение 4.** Почему для хранения ставки НДС (18%) лучше использовать константу, а не реквизит в справочнике? Что изменится, если ставку нужно будет менять?

---

## Ответы, указания, разборы

**К упражнению 1.** *Полное решение.*

(а) Список валют — **Справочник** (фиксированные сущности с возможностью добавления).  
(б) Факт оплаты — **Документ** (событие в жизни организации).  
(в) Курс доллара на каждый день — **Регистр сведений** (история значения по периодам).  
(г) Выручка за месяц — **Отчёт** (ответ на вопрос пользователя).  
(д) Автоматическое закрытие заказов — **Регламентное задание** (автоматическая задача по расписанию).

---

**К упражнению 2.** *Полное решение.*

(а) Текущий остаток товара — **Регистр накопления** (накапливает приходы и расходы, остаток = разница).  
(б) Цена три месяца назад — **Регистр сведений** с периодичностью (хранит историю значений в срезе по датам).  
(в) Бухгалтерский учёт по счетам — **Регистр бухгалтерии** (специализирован для двойной записи).

---

**К упражнению 3.** *Полное решение.*

```
РегистрыСведений.КурсыВалют  — Регистр сведений
Перечисления.СтатусыЗаказов  — Перечисление
Справочники.Валюты            — Справочник
```

---

**К упражнению 4.** *Полное решение.*

Константа хранит одно значение для всей системы. Если ставка НДС — константа, достаточно изменить её в одном месте, и весь код, который на неё ссылается, автоматически получит новое значение. Если ставку хранить в реквизите справочника — нужно найти нужный элемент, изменить его, и убедиться, что нигде не осталось жёстко заданного числа 18%. Константа — удобный инструмент, когда значение действительно едино для всей системы; если же ставка может различаться по подразделениям или периодам, понадобится другой механизм — например, регистр сведений.

---

*Карта объектов даёт ориентир в структуре конфигурации. Но у любой карты есть края — территории, которые за её пределами. В 1С такие территории есть: три темы, которые этот курс не охватывает, но с которыми предстоит столкнуться. § 8.4.*

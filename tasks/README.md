# Задачи для BSLexicon

Один файл — одна задача, `<slug>.yaml`. Имя файла становится `id`, если поле `id`
не задано явно. **Id менять нельзя никогда:** тренажёр хранит прогресс читателя
по ключу `<book_id>:<task_id>`, и переименование обнуляет чужую работу.

Собирается командой:

```
./book.sh tasks
```

Проверка идёт по [схеме контракта](../scripts/task-schema.json) и запускается ещё раз
перед релизом — задача, не прошедшая проверку, останавливает выпуск версии. Схема
приехала из BSLexicon, обновляется так:

```
curl -sL https://raw.githubusercontent.com/iMironRU/BSLexicon/main/docs/book-integration/task-schema.json \
     -o scripts/task-schema.json
```

## Один листинг — один источник

Код, который уже есть в тексте главы, помечается там тегом ` ```bsl,песочница ` и
**в `tasks/` не дублируется**. Песочница — про «прочитал и потрогал», задача — про
«решил и проверился». Разные роли, разные места. Две копии одного листинга разъедутся:
это ровно та болезнь, от которой в серии заведено правило единой нумерации.

## Формат

```yaml
title: "Сумма массива"
chapter: "05_massivy"          # слаг папки главы
section: "5.2"                 # § N.M — необязательно, для группировки
statement: |                   # plain markdown: без HTML и макросов книги
  Реализуй функцию `Сумма(М)` — возвращает сумму чисел массива.
  Пустой массив → 0.
starter: |
  Функция Сумма(М) Экспорт
      // Твой код
  КонецФункции
difficulty: easy               # intro | easy | medium | hard
tags: ["массив", "цикл"]
hints:
  - "Заведи накопитель и пройди массив циклом."
tests:
  - kind: call
    name: "три числа"
    invoke: "Сумма(Новый Массив(1, 2, 3))"
    expect: "6"
  - kind: call
    name: "пустой массив"
    invoke: "Сумма(Новый Массив)"
    expect: "0"
  - kind: call
    name: "отрицательные"
    invoke: "Сумма(Новый Массив(-5, 5, 10))"
    expect: "10"
    hidden: true
```

Второй вид теста — проверка вывода:

```yaml
tests:
  - kind: stdout
    expect: "Привет, мир!"
```

`expect` всегда строка, даже когда это число: сравнивается литерал BSL.

## Тесты — за читателя, а не против автора

Скрытые тесты (`hidden: true`) уместны для крайних случаев, но большинство должно быть
открытым. Читатель обязан понимать, что именно у него не сходится, иначе проверка
превращается в угадайку.

Контракт целиком:
[task-schema.md](https://github.com/iMironRU/BSLexicon/blob/main/docs/book-integration/task-schema.md).
